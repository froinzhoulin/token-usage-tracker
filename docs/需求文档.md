---

## 1. 背景与目标

### 1.1 背景

随着 LLM（DeepSeek、OpenAI、Anthropic 及其他国产模型）在日常开发与业务中的大量使用，Token 消耗分散在多个服务商、多个账号和多次会话中，缺乏统一视角来回答三个问题：

1. **花了多少**：总用量、总费用，以及它们随时间的趋势。
2. **花在哪**：按模型、会话、项目、日期维度的分布。
3. **是否失控**：用量/费用是否超出预期预算，需要提前预警。

### 1.2 目标

构建一款**本地运行、带图形界面**的 Token 用量统计与分析工具，帮助用户：

- 汇聚多渠道（文件导入、实时采集、手动录入）的 Token 使用数据；
- 以图表与明细两种视角查看统计结果；
- 按模型单价自动换算成本，支持预算与告警；
- 一键导出报表，便于归档与分享。

### 1.3 非目标（本版本不做）

- 不做多用户 / 账号体系与权限管理；
- 不做云端同步或远程部署（先本地单机）；
- 不做模型调用代理 / 转发 / 计费网关本身；
- 不做模型服务质量（延迟、质量）评测；
- 不做浏览器插件形态（如需可作为后续迭代）。

## 2. 用户画像与典型场景

**主要用户**：重度使用 LLM API 的个人开发者 / 研究者 / 内容创作者。

典型场景：

1. **月度对账**：月末汇总各服务商用量与费用，核对账单。
2. **项目预算管控**：给某个项目设定预算，接近上限时收到提醒。
3. **模型选型分析**：对比不同模型在同类任务上的实际 Token 消耗与成本。
4. **异常发现**：发现某天的用量异常飙升，定位到具体会话与请求。

## 3. 功能需求

### 3.1 数据接入（FR-1）

| 编号 | 需求 | 说明 | 优先级 |
| --- | --- | --- | --- |
| FR-1.1 | **用量记录文件导入** | 支持导入 JSON / CSV / NDJSON 格式的用量记录；用户可自定义字段映射（如输入/输出/总 Token、模型名、时间戳、会话 ID、成本） | P0 |
| FR-1.2 | **常见格式预置模板** | 预置 DeepSeek / OpenAI / Anthropic 官方 Usage 结构及常见日志格式的解析模板 | P0 |
| FR-1.3 | **实时事件采集** | 提供本地采集入口（如本地 HTTP 端点 / WebSocket / 落盘日志目录监听），应用运行期间可接收并入库实时用量事件 | P1 |
| FR-1.4 | **手动录入** | 表单录入单条用量（时间、模型、输入/输出 Token、成本、备注、项目/标签）；支持表格批量粘贴录入 | P1 |
| FR-1.5 | **导入预览与校验** | 导入前预览解析结果，标记无法解析或字段缺失的行，允许纠正后导入 | P1 |
| FR-1.6 | **去重** | 对同来源可识别的事件/行提供去重策略（按唯一事件 ID 或内容指纹），避免重复统计 | P1 |

### 3.2 统计与趋势分析（FR-2）

| 编号 | 需求 | 说明 | 优先级 |
| --- | --- | --- | --- |
| FR-2.1 | **汇总看板** | 展示总 Token、总费用、输入/输出/缓存 Token 汇总、记录条数、覆盖天数等核心指标卡 | P0 |
| FR-2.2 | **趋势图** | 按日 / 周 / 月 / 自定义区间展示 Token 用量与费用趋势（折线 / 柱状图），支持切换**总量、输入、输出、缓存**口径 | P0 |
| FR-2.3 | **维度分布** | 按 模型 / 会话 / 项目 / 标签 / 日期 分组统计（饼图 / 柱状图 / 排行表） | P0 |
| FR-2.4 | **时段与占比分析** | 时间范围同比/环比、各模型用量与费用占比 | P2 |
| FR-2.5 | **过滤与搜索** | 全局按时间范围、厂商、模型、项目/标签、会话关键词过滤统计视图 | P0 |

### 3.3 成本核算（FR-3）

| 编号 | 需求 | 说明 | 优先级 |
| --- | --- | --- | --- |

## 5. 技术方案（建议稿，供评审）

- **桌面框架**：Tauri 2（Rust + 系统 WebView），安装包小、内存占用低，适合个人工具；
- **前端**：TypeScript + React（或 Vue 3）+ 组件库（如 Arco / Ant Design），图表用 ECharts；
- **本地存储**：SQLite（经 Rust 侧访问，或 sql.js），负责明细与统计；
- **统计引擎**：Rust 后端提供聚合查询 API（按维度/时间分组、环比、预算进度）；
- **实时采集**：Tauri 内置本地 HTTP 服务（仅监听 127.0.0.1）接收用量事件，或监听指定日志目录变化；
- **导入解析**：Rust/TS 均可，采用“格式模板 + 字段映射”的解析器注册表，便于扩展；
- **告警**：Rust 侧定时任务扫描预算状态，经 Tauri 事件推送前端通知；系统通知用插件 `tauri-plugin-notification`。

> 待评审：框架是否锁定 Tauri 2 + React；如更偏好轻量 Electron，或偏好 Vue，需在评审时确认。

## 6. 数据模型（初稿）

核心实体：

- `provider`（厂商：deepseek / openai / anthropic / custom…）
- `model`（模型名、关联厂商、是否内置）
- `price`（模型单价版本：输入/输出/缓存 Token 单价、币种、生效区间）
- `usage_record`（时间、来源渠道、厂商、模型、会话 ID、输入/输出/缓存/总 Token、费用、币种、项目、标签、原始数据指纹、去重键）
- `project` / `tag`（分组维度）
- `budget`（范围、维度、周期起止、限额类型：量/费用、限额值）
- `import_batch`（导入批次、文件来源、成功/失败数，供追溯）

## 8. 验收标准（示例）

1. 导入一份包含 10 万行记录的 CSV，应用能正确入库且看板首次刷新 < 1s。
2. 某记录缺费用时，按所选模型单价自动换算，金额与人工核算一致（误差 < 0.01 元）。
3. 设置月度预算 100 元后，当累计费用 ≥ 80 元（80% 阈值）时，应用内出现告警。
4. 按“厂商 → 模型 → 会话”维度可逐层下钻，最终可定位到单条明细记录。
5. 关闭网络后，除“刷新价格库”外的全部功能可用。
6. 应用目录可整体备份，重装后能恢复全部数据与设置。

## 9. 风险与开放问题

| 编号 | 风险 / 问题 | 影响 | 应对建议 |
| --- | --- | --- | --- |
| R1 | 各家“记录文件”格式差异大，无法穷举 | 导入体验 | 模板预置 + 字段映射 + 用户自定义模板 |
| R2 | 价格随厂商调整而变化 | 成本计算偏差 | 价格库版本化 + 单价生效区间 + 一键更新 |
| R3 | “Token 数”各模型口径不一（如缓存命中、输出计费规则） | 统计口径偏差 | 记录原始口径，费用优先采用官方账单值 |
| R4 | 实时采集接入方改造成本 | 采纳率 | 先保证文件导入为主路径，实时为增强 |
| R5 | 桌面壳与系统 WebView 兼容性（Windows 老版本） | 分发 | Tauri 2 的 WebView2 依赖，文档明确安装要求 |

**待用户确认的开放问题**：
- Q1：是否需要“会话级对话详情”展示（如每条对话的请求/响应摘要），还是仅到“用量明细”为止？
- Q2：价格库币种默认人民币还是美元？
- Q3：M1 范围是否可接受作为第一版交付边界？

## 10. 附录：字段映射导入示意（FR-1.1）

| conversation_id | 会话 ID | 否 |

## 0. 已确认的技术决策（D1–D3，来自需求确认）

- **D1 明细粒度**：统计到"用量明细"记录级（时间/来源/厂商/模型/会话/输入/输出/缓存 Token/费用/标签），**不做**会话内对话内容解析展示。
- **D2 币种**：金额默认 **CNY** 存储与展示，界面支持切换 USD 显示（汇率按手动设置的固定汇率，不做实时汇率联网）。
- **D3 MVP 范围**：M1 MVP = 需求文档中的 **P0 全量**（文件导入 + 看板/趋势/分布 + 价格库与成本 + 明细 + CSV 导出 + 本地存储与备份）。P1/P2 项按里程碑 M2/M3 推进。

> 若以上默认需要调整，直接指出即可；实施顺序上最先做 M0（原型），不会浪费投入。

## 1. 技术栈（定稿）

| 层 | 选型 | 说明 |
| --- | --- | --- |
| 桌面框架 | **Tauri 2** | Windows 优先，跨平台兼容 |
| 前端 | **React 18 + TypeScript + Vite 6** | 组件库后续引入（先轻量手写，避免早期锁定） |
| 图表 | **ECharts 5** | 折线/柱状/饼图、下钻联动 |
| 后端（Rust） | Tauri Command + 独立 domain 模块 | 聚合统计、导入解析、价格换算、预算扫描 |
| 存储 | **SQLite**（rusqlite 编译进 Rust 侧） | 明细/价格/预算/设置 |
| CSV 解析 | 前端 `papaparse`（导入预览） | 与需求 FR-1.5 预览校验对应 |
| 实时采集 | Tauri 本地 HTTP（127.0.0.1）或日志目录监听 | M2 实现 |
| 系统通知 | `tauri-plugin-notification` | M2 告警渠道 |
| 状态管理 | 轻量：React Context + hooks（数据量可控） | 不引入重型状态库 |
| 样式 | 原生 CSS + CSS 变量（暗/亮主题预留） | 减少依赖 |

## 2. 架构

```
┌─────────────────────────────────────────────┐
│  React UI (Vite dev / dist)                 │
│  ├ 页面: 看板 / 明细 / 导入 / 预算 / 设置      │
│  ├ hooks: useUsageStats / useRecords ...     │
│  └ api: window.__TAURI__.invoke 封装          │
└───────────────┬─────────────────────────────┘
                │ Tauri IPC (JSON, Command)
┌───────────────▼─────────────────────────────┐
│  Rust core (src-tauri)                       │
│  ├ commands: 按 功能域 拆分 (stats/records/  │
│  │            import/price/budget/settings)  │
│  ├ domain: 计算与规则(价格换算/聚合/预算判定)  │
│  ├ db: SQLite 连接、迁移、schema              │
│  └ watcher: (M2) 实时采集/目录监听             │
└───────────────┬─────────────────────────────┘
                │ rusqlite
        ┌───────▼───────┐
        │  SQLite 文件    │  用户数据目录 token-usage-tracker/data.db
        └───────────────┘
```

分层原则：**Command 层只做参数校验与序列化，业务规则全部在 domain**，便于单测与后续扩展新数据源。

## 4. 数据模型（SQLite DDL 定稿草案）

```sql
-- 厂商与模型
CREATE TABLE provider (id INTEGER PRIMARY KEY, code TEXT UNIQUE NOT NULL, name TEXT NOT NULL);
CREATE TABLE model (
  id INTEGER PRIMARY KEY, provider_id INTEGER NOT NULL REFERENCES provider(id),
  name TEXT NOT NULL, builtin INTEGER NOT NULL DEFAULT 1, UNIQUE(provider_id, name));

-- 单价版本化: 每个(模型,币种)存生效区间,便于随价格更新回溯
CREATE TABLE price (
  id INTEGER PRIMARY KEY, model_id INTEGER NOT NULL REFERENCES model(id),
  currency TEXT NOT NULL DEFAULT 'CNY',
  input_per_mtok REAL NOT NULL, output_per_mtok REAL NOT NULL, cached_input_per_mtok REAL,
  effective_from TEXT, effective_to TEXT, source TEXT DEFAULT 'builtin'|'custom');

-- 用量明细(核心)
CREATE TABLE usage_record (
  id INTEGER PRIMARY KEY,
  recorded_at TEXT NOT NULL,          -- ISO8601 UTC
  source TEXT NOT NULL,               -- import_csv|import_json|manual|live
  batch_id INTEGER REFERENCES import_batch(id),
  provider_code TEXT, model_name TEXT,
  session_id TEXT, request_id TEXT, dedup_key TEXT UNIQUE,
  prompt_tokens INTEGER, completion_tokens INTEGER, cached_tokens INTEGER,
  total_tokens INTEGER,
  cost_amount REAL, cost_currency TEXT,   -- 记录自带费用(优先)
  cost_source TEXT,                    -- official|computed|null
  project TEXT, tags TEXT,             -- tags JSON 数组
  note TEXT,
  raw_fingerprint TEXT);

CREATE TABLE import_batch (id INTEGER PRIMARY KEY, file_name TEXT, imported_at TEXT,
  total_rows INTEGER, ok_rows INTEGER, failed_rows INTEGER, mapping_json TEXT);
CREATE TABLE budget (id INTEGER PRIMARY KEY, name TEXT, scope TEXT, scope_value TEXT,
  period TEXT, limit_type TEXT, limit_value REAL, thresholds_json TEXT, active INTEGER);
CREATE TABLE kv_settings (key TEXT PRIMARY KEY, value TEXT);  -- 币种/汇率/默认区间
```

索引：`usage_record(recorded_at)`、`(provider_code, model_name)`、`(project)`、`dedup_key UNIQUE`。
金额一律 REAL 存元，4 位小数精度通过 domain 层四舍五入控制。

## 5. Rust Command / 前端 API 草案（v1 接口清单）

| Command | 输入 | 输出 | 对应需求 |
| --- | --- | --- | --- |
| `import_file(path, mapping)` | 文件路径+列映射 | 批次结果(成功/失败行+预览错误) | FR-1.1/1.5 |
| `list_records(filter, page)` | 过滤+分页 | 明细页 + total | FR-4.1/4.2 |
| `update_record(id, patch)` / `delete_record(id)` | — | ok | FR-4.3 |
| `usage_stats(filter)` | 时间范围/维度 | 汇总卡片+趋势序列+分布 | FR-2.1~2.3 |
| `list_models_prices()` | — | 模型+单价 | FR-3.1 |
| `upsert_custom_price(model, prices)` | — | ok | FR-3.2 |
| `compute_costs(filter, dry_run)` | — | 为缺失费用记录换算 | FR-3.3 |
| `export_records(filter, format, dest?)` | CSV/Excel/JSON | 文件路径或保存对话框 | FR-5.x |
| `upsert_budget` / `list_budgets` / `budget_progress()` | — | 预算+进度 | FR-6.x |
| `get_settings` / `set_settings` | — | kv | FR-7.3 |
| `backup_db(dest)` / `restore_db(src)` | — | ok | FR-7.1 |

> Excel(.xlsx)导出在 M2 引入（避免 MVP 引入过重依赖）；MVP 导出 CSV+JSON。

## 8. 风险与对策（补充需求文档第 9 章）

| 风险 | 对策 |
| --- | --- |
| Rust 首编耗时(数百 crate) | M0 尽早执行 `cargo build`，后续增量编译 |
| Tauri dev 需长时间运行验证 | 用 `cargo check`/`vite build` 做 CI 级校验，dev 窗口由人工抽查 |
| papaparse 大文件卡 UI | 主线程仅做解析预览(限行数),入库放 Rust 异步 Command |
| 金额精度 | 全部 REAL+元，展示层 2~4 位；文档明确换算口径 |
